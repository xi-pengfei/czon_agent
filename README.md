# czon_agent

面向企业内部使用的精简 Python AI 智能体。应用自身提供登录、角色权限、历史会话、模型管理、Skills、工具策略、附件、实时输出和主动停止；WebUI 使用 React、TypeScript 和 Vite，生产运行仍只有 Python/FastAPI 服务。

## 首次启动

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py webui
```

本机访问 `http://127.0.0.1:8000`；同一局域网访问 `http://服务器的局域网IP:8000`。首次打开网页时，直接为固定管理员账号 `admin` 设置密码，不使用临时密码。

登录后由系统管理员在“模型配置”页面添加模型和 API Key。模型密钥加密保存在本地数据库，不再从 `.env` 读取。

以后启动命令不变：

```bash
source .venv/bin/activate
python main.py webui
```

也支持 CLI：

```bash
python main.py
python main.py "帮我列出 workspace 下的文件"
```

## 配置边界

`config.yaml` 只保留机器和运行时配置：

- `active_provider`：CLI 默认模型。
- `skills`、`workspace`：目录和全局 Skill 开关。
- `agent`：总运行时间、连续异常、模型连接/读取/写入超时和有限重试。
- `tool_policy`：底层工具安全策略。
- `webui.host`、`webui.port`：监听地址和端口。
- `webui.session_db`：用户、权限、模型、审计和会话数据库。
- `webui.cookie_secure`：全站 HTTPS 时设为 `true`，HTTP 直连时为 `false`。

`.env` 只保存 PledgeBox、数据库、金蝶等业务系统凭据。模型清单、连接信息和 API Key 全部以数据库为唯一管理来源，主智能体和业务 Skill 使用同一个模型解析入口。

## 用户与管理

管理员登录后访问独立管理页面：

- 用户：创建、启停、分配部门和角色，设置用户月 Token 额度并重置临时密码。
- 组织：维护任意层级部门和部门默认月 Token 额度。
- 角色：通过搜索多选限制 Skills、`read`、`write`、`bash`、`activate_skill` 和模型。
- 模型：管理 OpenAI 兼容接口、模型名、多模态/工具/流式能力，测试连接并读取模型列表。
- 日志：分别查看用户、角色和模型管理审计，以及脱敏后的运行日志。

模型 API Key 只能在管理页面填写。Key 使用 `data/czon_agent.key` 加密后保存，页面只显示“已配置”，编辑时不会返回旧值。

## 会话与执行

- 历史会话保存在 `data/czon_agent.db`，普通用户只能访问自己的会话。
- 登录使用浏览器会话 Cookie，30 分钟无操作或登录满 8 小时后失效。
- 输入 `/` 可选择当前角色允许的 Skill，后端仍会再次校验权限。
- 模型回答和 shell 进度通过 SSE 实时显示。
- 新生成的成果文件绑定到用户和会话，回答下方可直接下载；其他账号不能访问。
- 回答保存运行时间和真实 Token 用量，管理页面按百万 Token（`M`）展示月额度。
- WebUI 停止会终止对应子进程组；CLI 使用 `Ctrl+C`。
- 正常任务不按固定轮数中断，仍保留总时间、断连和连续异常保护。

## 小智 MCP（可选）

独立进程连接小智官方 MCP 接入点，复用 Agent、Skills、模型和账号权限。
不增加草稿或额外确认流程，Skill 支持的操作会真实执行。

1. 在 WebUI 完成 admin 初始化并配置模型；小智默认绑定 admin，沿用其权限。
2. 安装项目依赖：`python -m pip install -r requirements.txt`（已安装则无需重复操作）。
3. 无需修改 `config.yaml`，运行小智命令即启动，停止进程即关闭。账号默认 `admin`；模型优先使用
   `CZON_ACTIVE_PROVIDER`、可选的 `xiaozhi.provider`、`active_provider`，都未设置则选数据库中
   已启用、有密钥且账号有权使用的第一个模型（按配置名称排序）。无需重复填写模型信息。
   如需更换账号，可选填 `xiaozhi.username`。网页保存在浏览器里的模型选择不影响小智。
4. 在 `.env` 添加 `XIAOZHI_MCP_ENDPOINT=小智后台提供的完整wss接入地址`，不要提交密钥。
5. 执行 `python main.py xiaozhi`，看到“小智 MCP 已连接”后，在小智后台检查工具上线。

本地电脑可直接测试，无需公网入站端口或 WebUI 同时运行；需要保持电脑联网。
小智角色建议：业务操作调用 business_request；简短播报 summary，不读 JSON；
追问补充沿用 conversation_id，新业务留空。超时不要自动重新创建单据。
completed 表示 Agent 本轮结束，不保证业务成功，实际结果以 summary 为准。

小智产生独立的 `[小智]` 历史会话，登录绑定账号可在网页查看请求、回答及用量。
仅保存用户请求和最终回复（沿用现有会话记录），不额外保存完整内部工具日志。
进程重启后开启新会话；当前只支持一个绑定账号、一个同时执行的请求。
长任务受小智侧工具超时限制，第一版没有异步任务查询或主动播报，建议先测试短查询。
连接重连不会主动重发请求，但不能阻止模型再次调用同一业务；防重复建单仍应由业务 Skill/API 保障。
可用 `python main.py xiaozhi-stdio` 接入标准 MCP 客户端进行协议调试。

接入方式参考：[小智 MCP 示例](https://github.com/78/mcp-calculator)。

### 小智只读查询示例

已内置 `kingdee-voice-query`（金蝶商品概况快查）。对小智说：
“请使用金蝶商品概况快查技能，查一下金蝶有多少个商品，给我一个示例。”
该技能只查一次商品列表，返回总数及最多三条样例，不扫描全库、不生成文件或创建单据。
脚本：`python skills/kingdee-voice-query/scripts/query.py`。
输出包含固定的 `summary`、`data` 和 `timings_ms`，可用于跨入口对照。
脚本阶段进度不等于机器人主动播报；每十秒连续语音反馈仍需单独验证小智端支持。

### 等待播报实验（不执行业务）

新增 `wait_demo` 工具后需重启小智进程，并在后台刷新工具列表。
对机器人说：“做一次等待播报测试，使用 wait_demo，每次先读出返回的短句，再继续查询，直到结束。”

工具模拟约25秒的等待；首次立即返回开始提示，后续每次最多等待10秒后返回预设短句，最终返回完成。
反复调用使用同一个 task_id，不会调用 Agent、金蝶或任何业务 Skill。
如果角色介绍原来要求所有请求只能调用 business_request，请增加例外：
“用户明确要求等待播报测试时使用 wait_demo；running 时先语音播报 summary，再传回 task_id 继续调用；completed 时停止。”

这是多次工具调用之间的播报实验，不是在同一次工具调用中推送语音，不保证固定十秒播报。
本地日志只能确认工具被调用、返回了什么状态，不能确认设备实际播放；需要现场听取验证。
本实验不会为已有业务任务自动插播短句，也不会改变其同步执行方式。

### 多会话、账号同步与大屏

WebUI 任务现在独立于浏览器连接运行。新建/切换会话、刷新、关闭页面不会停止任务；“停止当前任务”只停止选中的运行。不同会话默认每账号最多并行 3 项，全服务合计最多 3 项，同会话按提交顺序执行，额外任务排队。队列总容量为 32，每账号最多 8 项等待任务；满载时明确拒绝提交。

同账号登录的网页自动同步会话列表、运行状态和流式内容，无需手动订阅。普通网页保持正在查看的会话；直接访问 `/display` 自动跟随最新提交的会话；从工作台点击“大屏模式”先保持当前会话，随后跟随新提交的任务。大屏仍是浏览器，音频走该设备的默认扬声器/HDMI 输出；多个并行任务不会混在同一段回答中播放。

- 默认不开声音；在需要播放的设备点击“开启播报”。浏览器可能要求本次页面先有用户操作。同一标签页通过“大屏模式／返回工作台”切换会保留播报开关、当前音频和队列；刷新、另开标签页或换设备需要重新开启播报，不会重播过去的整篇回答。
- 播报与正文分开：只播关键进度和经过口语整理的摘要，正文完整保留。播放当前段时提前准备下一段音频；语音失败不会停止业务或文字同步。
- 默认显示易读进度，命令和工具日志保留在可展开的详情中。无声模式的等待提示 4 秒后显示，约每 20 秒更新，可点击“不再显示”关闭。开启播报后，等待文案显示在语音摘要中并读出，不再重复显示底部提示。
- 会话成果目录为 `workspace/users/<账号摘要>/sessions/<会话ID>/`。同会话后续任务复用文件；升级后首次使用旧会话时，从该会话已登记的成果副本恢复文件，不复制其他会话的资料。
- 这是任务和成果归属隔离，不是 OS 安全沙箱。任意 Shell 仍运行在服务账号权限下；写死全局路径或修改相同外部单据的 Skills 仍需各自的业务锁与幂等检查。已有小智 MCP 独立进程未并入这个 WebUI 调度器。

在 `config.yaml` 的现有 `webui` 节下可选增加：

```yaml
runs:
  max_workers: 3
  per_owner: 3
  max_pending: 32
```

**部署保持一个 WebUI 进程。**执行器会锁定数据库旁的 `.runs.lock`，防止同一数据库启动多个执行器；不能用增加 Uvicorn workers 的方式扩容。线程池负责业务并发。服务重启后，遗留任务标记“中断，结果待核实”，不会自动重做可能已经写入外部系统的操作。

数据库自动新增 `agent_runs`、`agent_events` 和消息 `run_id` 列，保留旧消息。事件按序持久化，重连可补齐；删除非运行中会话时同时删除其运行和事件。当前事件保留至会话删除，长期部署需监控数据库容量。上传文件保留至原有的 24 小时清理流程，以支持排队和重复请求。

### 可选语音识别与合成

录音入口位于发送按钮前。首次点击检查浏览器和服务能力，录音最长 60 秒。通过 AudioWorklet 连续采集，在短句停顿处或约 5 秒时生成独立 WAV 分段，按顺序识别并追加到输入框，由用户检查后发送；切换会话会释放麦克风并取消尚未完成的请求，切到后台会结束录音。识别积压时自动结束采集、处理已有录音，失败时保留已识别文字。移动端必须通过 HTTPS 访问（开发机 localhost 除外），并使用支持 AudioWorklet 的浏览器。语音服务独立于聊天模型配置，不会自动复用模型密钥。

硅基流动当前使用文件转写接口，因此这是分段转写（存在分段和请求延迟），不是逐字实时 ASR。分段会增加请求次数，连续讲话的切分处也可能影响识别准确率；需要稳定的逐字临时结果时应另接实时 ASR 接口。录音中及最后一段识别期间不能发送，避免误发不完整内容。手机回车默认换行，使用发送按钮提交。

在服务启动环境中配置 OpenAI-compatible Audio API：

```dotenv
CZON_SPEECH_API_KEY=<语音服务密钥>
CZON_SPEECH_BASE_URL=https://your-speech-service.example/v1
CZON_ASR_MODEL=whisper-1
CZON_TTS_MODEL=tts-1
```

模型名应换成所选服务实际支持的名称。也可通过 `config.yaml` 可选 `speech` 节设置 `base_url`、`asr_model`、`tts_model`、`voice`（默认 `alloy`）；密钥只从环境读取。

开启播报后，客户端按需请求 `POST /api/runs/{id}/narration`。服务端从该账号的任务快照提取公开回答，用任务原来选择的大模型进行无工具的口语整理（会产生额外模型用量），不会改写页面答案或重新执行业务。任务持续执行时约每 20 秒可播一次真实状态和简短陪伴语，即使之前已经出现文字也不会停止进度播报；有新结果时优先播结果并丢弃排队中的旧提示。进度事实由任务状态确定，LLM 只补充结合任务主题的轻巧比喻或温和趣话，严肃场景不强行讲笑话；不朗读内部推理、命令或日志，不估算剩余时间。瞬间完成的准备步骤合并说明，不逐个读毫秒数；结果提炼关键事实和需要用户处理的事项，表格先转为可供摘要使用的数据。长回答最多整理三段中间摘要和一段剩余结果摘要，避免长时间照读整个报告。模型失败时只说简短提示，已停止/失败的任务会取消待播音频。

等待文案按账号、任务、阶段及 20 秒时间窗缓存，多端共用；持续等待约每分钟最多三次常规文案生成（阶段切换可能另生成），语音合成另计用量。关闭声音后如仍显示底部提示，依然会生成等待文案；隐藏提示可停止该页面的无声提示请求。模型不可用时仅播真实进度。结果文本整理按账号、任务、内容和口播前文缓存；当前音频播放时最多预备下一段，关闭播报或切换会话会清空待播内容。播放器显示“语音摘要”，便于核对实际说了什么。没有语音密钥时仍可使用设备内置声音，但文案整理会使用已配置的任务大模型，不能保证系统音色的自然度。硅基流动 CosyVoice2 默认附加自然、沉稳的语气指令，可用 `speech.style` 覆盖，设为空字符串可关闭；其他服务不发送这类模型专用指令。

本实现改善口语表达和音频段间的网络等待，仍属于段落合成加预备播放，不是小智的 Opus 音频帧协议或端到端实时语音模型。修改口播后端后需要重启 WebUI；小智 MCP 的业务接口和部署方式不变。

语音音频/文字会发送至你配置的语音服务，请按企业数据要求选择本机、内网或云服务。未配置语音密钥时录音识别入口会解释缺少配置；播报可回退到浏览器内置语音，声音和可用性取决于操作系统。服务端合成按账号缓存到 `data/speech/`，不作为公开静态资源，需结合企业保留策略清理。

接口：`POST /api/runs` 幂等创建；`GET /api/runs` 返回账号快照与游标；`GET /api/events` 自动同步；`GET /api/runs/{id}/events` 按运行重放，支持 `Last-Event-ID`；旧 `POST /api/chat/stream` 保留兼容。所有读取按登录账号鉴权，写入继续要求 CSRF。

验证命令：`python -m unittest discover -s tests -q`；`cd frontend && npm run build`。真实 ASR/TTS、手机麦克风授权与工厂屏幕音响需在配置服务后进行设备验收。

手机登录布局、局域网 HTTPS 证书配置以及声音试听/恢复步骤见 [手机访问与语音配置](docs/mobile-https.md)。
