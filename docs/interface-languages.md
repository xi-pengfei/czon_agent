# 界面多语言

当前提供简体中文、繁体中文和英文，默认简体中文。使用 i18next + react-i18next；三份语言资源随前端构建打包，切换时不调用翻译服务，不需要 API Key。

## 使用

- 登录页：登录卡片上方的「界面语言」。
- 工作台：屏幕右上角的语言下拉框（与模型选择框同款样式）。
- 管理后台：顶部的语言选择。
- 大屏：右上角的语言选择。
- 选择保存在当前浏览器、当前站点的 localStorage（`czon.ui.language`）。刷新后保留，不向其他设备强制同步；存储不可用时本页仍可切换。
- 切换不会刷新页面或重建聊天组件，当前草稿和任务保持原状。

## 文案原文件

| 文件 | 用途 |
| --- | --- |
| `frontend/src/locales/zh-CN.json` | 简体中文原文 |
| `frontend/src/locales/zh-TW.json` | 繁体中文对应版本 |
| `frontend/src/locales/en.json` | 英文对应版本 |

三份文件采用相同的中文原文键。例如：

```json
{"新任务": "New task", "编辑 {{value0}}": "Edit {{value0}}"}
```

修改翻译时只改右侧值，保留键和 `{{value0}}` 等参数占位符。当前键为完整文案，含句点和冒号也按普通文字处理。新增文案时在三份文件同步增加键，并在界面使用 `t("新文案")`。英文由本次改造整理，繁体文案先使用 OpenCC 转换后检查；均可人工调整，不是在线自动翻译。

修改后运行：

```sh
node --test frontend/tests/*.test.mjs
npm run build --prefix frontend
```

构建产物写入 `webui/`。刷新页面即可加载新版本，单独修改界面文案不需要重启 Python 服务。

## 边界

- 翻译登录、聊天控件、固定任务状态、语音控件提示、管理页面和已收录的账号错误提示。
- 用户名、Display Name、模型名称、部门/角色名称及技能名称/说明按照原值显示。没有修改任何 Skill 文件及其格式，也没有新增多语言 Display Name 字段。
- 用户消息、AI 回答、任务进度的模型摘要、报表及日志原文不翻译。回答语言继续由 Skill 和用户请求决定，不给模型额外注入语言指令。
- 未收录的服务端/第三方错误保留原文，便于排查；后续可逐条增加固定错误文案。
- 录音、ASR、TTS 服务、音色、并发设置及小智 MCP 不因选择界面语言而改变。
- 繁体界面采用 zh-TW 的日期格式；英文采用 en 的日期格式。业务原始日期文本不转换。

## 验证

前端测试覆盖语言资源键和参数一致性、语言切换与存储、HTML lang 更新，以及用户内容保持原样。保留录音取消/发送、语音队列和文本流等回归测试。浏览器已实测工作台中英繁切换、输入草稿保留和刷新后语言保留。
